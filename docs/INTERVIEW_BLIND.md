## 第一部分：5 分钟自我介绍（练读稿，~750 字）

> 语速 ~150 字/分钟，**练的时候录音**，回放检查时间卡得准不准。

[00:00 - 00:30] **Hook — 我是谁 + 我做了什么**

> 面试官你好，我叫李志泉，澳门人，在水务行业做了 5 年工程师。
> 
> 今天想聊的是我自己做的一个项目 —— 用数据工程加 AI 的方式，重新解决水务里"漏损分析"的老问题。简单说，**9,963 个真实水表，4 个 DMA 区域，151 天的逐时数据**，我搭了一套从异常检测、7 天预测、到自然语言查询的完整链路。

[00:30 - 01:15] **真实痛点驱动**

> 这个项目不是凭空做的。水务行业有一个核心痛点叫 **NRW（Non-Revenue Water，产销差）** —— 主管和分表的读数差，就是漏掉的水、偷的水。**全球水务平均漏 30%**。
> 
> 我之前的工作是工程师，**每天的痛点**就是：业务方问我"上周路氹城 DMA 异常有几个"，我得花 1 小时手写 SQL；异常检测全靠老工程师的经验，没量化；预测靠 Excel 趋势外推，精度很差。
> 
> 所以这个项目就是**把我的日常痛点用数据工程加 AI 重做一遍**。

[01:15 - 02:30] **技术架构 — 三件事讲清楚**

> 项目分三块：
> 
> 第一块，**数据工程**。Excel 每天来一份，我写了一个增量转换器（incremental converter），用 daily_totals.json 缓存做增量更新，每天处理新数据 ~55 秒；全量重派生 151 天大概 2 小时。
> 
> 第二块，**机器学习**。两个模型 —— 异常检测用 14 天滚动 Z-score 加 tanh 压缩，分 spike / drop / zero / watch 四类，~1,500 个异常；7 天预测用 Top-50 水表的 LinearRegression，加周末、趋势、季节性特征。
> 
> 第三块，**AI Agent**。LangChain 加 FastAPI，**13 个工具分两类**：10 个读预聚合的 JSON 工具（dashboard 那种结构化查询用），3 个 text-to-SQL 工具（ad-hoc 自由查询用）。Multi-agent 模式可切，复杂问题用 Planner → Executor → Synthesizer，延迟 1 秒到 4 秒，但答案质量明显好。

[02:30 - 03:30] **MLOps 工程质量 — 区别于"玩具项目"的关键**

> 除了功能，还有一套**生产级 MLOps 管道**：
> 
> 6 阶段 pipeline —— 读取、清洗、异常检测、预测、写 SQLite、漂移检测，**每个阶段有 checkpoint**（故障恢复从 1 小时降到 10 秒），**每个阶段出口有 pandera schema 校验**，drift stage 用 KS 检验加卡方检验对比基线。
> 
> 25 题 QA 评估套件，关键词召回率 70% 左右。
> 
> GitHub Actions CI、pytest 39 个测试、Docker 一键起、gitleaks 密钥扫描。

[03:30 - 04:15] **为什么投 HKT**

> 为什么投 HKT —— **结构是同构的**。把"水表"换成"基站"、"漏损"换成"客户掉线率"、"DMA"换成"网络区域"，业务逻辑是同一套。**HKT 有真实的数据、有结构化的问题、有工程师的痛点**，我这套架构不是只能解决水务，是一套**可迁移的工程方法**。
> 
> 另外我个人想跳出"舒适区" —— 在水务做 5 年，技术栈在原地打转。我想在一个**更工程化、更重视数据**的团队里学。

[04:15 - 04:45] **我能给团队带来什么**

> 我能带来的，3 件事：
> 
> 1. **Domain + 工程双视角** — 5 年水务业务理解，加上完整的端到端 pipeline 经验，不只是跑模型
> 2. **真实项目经验** — 9,963 meter 真实数据 + 151 天，不是在 toy dataset 上 demo
> 3. **诚实** — 我知道什么做好了、什么没做（detection 在 real 模式是 validator 不是 recomputer，backtest 没做），能清楚告诉团队技术债在哪

[04:45 - 05:00] **收尾**

> 我的 GitHub 是 github.com/a597054929-stack，仓库 README 和 docs/ 里有完整的架构说明。期待和您聊具体的细节。

## 第二部分：盲问 Q&A（12 题，面试官没看作品）

> 面试官听完 5 分钟自我介绍后，**只根据他听到的内容**追问。可能的方向：
> - 自我介绍里有数字 → 想验证
> - 自我介绍里有技术选型 → 想了解 trade-off
> - 自我介绍里有 pivot → 想了解动机
> - 自我介绍里有"诚实承认" → 想挖深

### Q1: "你说 9,963 个水表、151 天 — 这数据怎么拿到的？"

🔍 听：你怎么接触到真实生产数据？有 NDA？公开数据？同事给？

A: 真实情况是**澳门自来水股份有限公司**提供给我的历史抄表数据，有内部授权使用。9,963 meter 是当前在册水表数，151 天是 2026 年 1 月 1 日到 5 月 31 日。**数据已经做了脱敏**（meterId 是 hash，不是合同号），不能反推具体住户。

**诚实补充**：这部分数据**没有公开版本**，所以面试 demo 用的 mock generator（500 meter）能展示架构，真实数据验证过的逻辑可以平移但要重新跑。

---

### Q2: "你说异常检测 14 天滚动 — 为什么不是 7 天或 30 天？"

🔍 听：参数选择背后的思考

A: **业务约束驱动**。14 天 = 2 个完整周，剔掉周内波动（住宅区周一和周末用水差很大）。7 天会漏掉周效应；30 天太长，模型对"这周新出现的高峰"反应太慢。

实际调过：mock 阶段用 7 天测试过，spike 误报率高 30%，调成 14 天后稳定。**真生产应该 rolling window 调参**，但我目前是 14 天固定，因为业务方要"可解释的简单规则"。

---

### Q3: "你说增量更新 55 秒 — 我不信。151 天 × 9,963 meter 怎么可能那么快？"

🔍 听：会不会在吹牛？细节经不经得起问？

A: **关键是"反派生"而不是"重读 Excel"**。流程：
1. Converter 读 daily_totals.json 缓存（~100KB 字典）
2. 读 1 个新 Excel（~25K 行，~50s，openpyxl 慢）
3. 合并 merged = {**cache, **new_daily}（内存 dict merge）
4. 从 merged 全量算 daily_dma / daily_top20 / anomalies（~1s，9,963 meter × 151 天 = 150 万次 sum，Python list comprehension）
5. INSERT OR IGNORE 到 SQLite（~1s）

**慢的 50s 就是 openpyxl 解析 25K 行 Excel**。新数据进来只需要读 1 个文件，历史 150 天不重读。

---

### Q4: "你提到 NRW — 你的异常检测能直接定位漏损点吗？"

🔍 听：业务和技术的连接 — 这是 senior 标志

A: **不能直接定位漏损点**，但能给线索。算法层面：
- **drop 类异常**（消费突降 70%+）= 怀疑管道破裂 / 偷接导致水流改道
- **spike 类异常** = 怀疑私接大用户 / 读数传感器故障
- **零值** = 怀疑表故障 / 拆表

**但漏损定位还需要 GIS 拓扑 + 压力传感器**，不在我的项目里。我做的是"哪户可疑"，工程师拿到这个 list 后去现场核查。**模型给 candidates，物理验证靠人**。

### Q5: "你为什么从水务转 DS？你之前是工程师，现在招的是 DS 岗位，team 怎么信你能转？"

🔍 听：转行动机 + 现实主义

A: **不是"想转 DS"，是"想换工具"**。我 5 年水务最痛的不是模型不会用，是 SQL 写烦了 + Excel 卡死了。**这个项目就是工具升级**。

可信度靠**项目证明**，不是简历文字：
- 完整 MLOps pipeline（不只是 notebook）
- 真实数据、真实 schema、真实失败案例
- 25 题 QA 评估，能 show 出 70% recall 这个数字

**诚实说 gap**：我**没做过大规模生产部署**（百万级用户 / TB 级日志），没带过 DS 团队（3-5 人），所以投的是**senior 偏 IC / staff 下沿**的岗位，不是 manager。**清楚自己的级别，不夸大**。

### Q6: "你说 LangChain — 现在 2026 年 LangChain 已经不是首选了，你怎么看？"

🔍 听：会不会被技术热点牵着走？有没有自己的判断？

A: **诚实说 LangChain 抽象层偏厚**，调试困难。我用 LangChain 主要因为：
1. **工具注册的标准化**（13 个 tool 一行 `@tool` 装饰器）成熟稳定
2. **ReAct agent 模板**直接可用
3. **生态**：LangSmith tracing、agent evaluation 都有

但**核心逻辑不绑 LangChain**。我的 system prompt 是手写的、tool_router.py 是手写的、agent_executor.py 里我重写了 streaming logic。**LangChain 是 glue，不是 brain**。

2026 年如果重写，可能考虑 **DSPy**（编译优化 prompt）或 **PydanticAI**（更 Pythonic 的工具定义）。**但"换框架"不解决业务问题**，所以现在没动。

---

### Q7: "你说 multi-agent — 我用 single agent 加 tool 也行啊，multi-agent 是不是过度设计？"

🔍 听：架构选择 + 成本意识

A: **对简单问题 multi-agent 是过度设计**。UI 切 checkbox 默认关闭 — 单问题 single agent 一次调用 ~1s。

**multi-agent 价值**只在复合问题："对比 A 和 B 过去 7 天的预测精度" — 需要先 plan（决定调哪些工具）、再 execute、最后 synthesize。**3 次 LLM 调用**不是浪费，是必要的解耦。

**真实成本数字**：
- single agent 简单问题：1 次 LLM，~1s，cost 1x
- multi agent 复杂问题：3 次 LLM，~4s，cost 3x
- 收益：复杂问题答案质量明显好

**业务取舍**：技术问题用 multi，闲聊用 single。**不做"永远 multi"**。

---

### Q8: "你 5 分钟里说 9963 meter — 4 个 DMA 区域 — 43 种物业类型。能讲个具体 case 吗？"

🔍 听：会不会只是背数字，case 经不经得起挖

A: 具体 case：**2026 年 3 月 15 日路氹城區的异常 spike**。
- 触发条件：当日 1 户酒店水表消费突增 8 倍均值
- 算法：14 天 Z-score = 12.3，tanh 压缩后 score = 0.95
- 分类：spike（mean × 4 阈值过 + score > 0.5）
- 实际原因：现场核查发现是**新接入的餐饮租户**（之前没在册），合法消费

教训：**算法报警 ≠ 漏损**。spike 可能是商业扩张（合法）也可能是私接（违法）。**模型给 candidates，业务方 decide**。

---

### Q9: "你说 pandera schema 校验 — 怎么知道 schema 改了你不会漏掉？"

🔍 听：MLOps 经验的深度

A: 三道防线：
1. **Schema 作为代码** — `pipeline/schema.py` 写在 git 里，PR review 时人会看
2. **Pipeline 早 fail** — schema 不对 ingest 阶段就抛，不会污染下游
3. **Drift stage 兜底** — 即使 schema 没显式改，**值的分布变了** KS-test 也会报警

**真实案例**：1 月我加 4 个新 DMA 区域时忘了改 `VALID_DMAS` 列表，pipeline 跑到 `detect_anomalies` 立刻报 "value not in allowed set"。**没让错误数据进 SQLite**，没污染 agent。

---

### Q10: "你说诚实 — 那你的项目最大的不足是什么？"

🔍 听：自省能力

A: 三个真实的不足：

1. **没做 backtest** — 我的预测是用 train-on-all 历史数据，**没做 rolling window CV**。生产里应该每加 7 天评估预测 7 天的 MAPE，看模型是否漂移。**已知缺口，没补**。

2. **没做 semantic eval** — agent 评估靠关键词 recall（70%），LLM 答对但用不同词就算 0。**应该用 LLM-as-judge** 或 human eval。

3. **没监控生产** — drift detection 实现了，但**没接 PagerDuty / Slack**。生产部署要补告警通道。

**改进优先级**：backtest > semantic eval > 告警通道。

## 练习流程建议

### 第一次：自己读稿
1. 读 5 分钟自我介绍**两次**，计时
2. 找出卡顿 / 超时 / 太抽象的句子
3. 改 3-5 个词，让它听起来像你自己

### 第二次：录音回放
1. 完整 5 分钟自我介绍，录音
2. 听回放，标记 [叹气] [停顿 > 2s] [看稿腔] [语速突快]
3. 重录同样的版本，对比

### 第三次：盲问模拟
1. 让朋友/家人当面试官，**不给看项目**，只听完 5 分钟自我介绍
2. 朋友自由问 10 分钟，记下问题
3. 对照 Q1-Q12，看哪些没准备
4. 补缺

### 第四次：综合
1. 完整模拟：**5 分钟自我介绍 + 30 分钟 Q&A**
2. 录像，回放
3. 关键检查点：眼神、节奏、自信 vs 紧张
